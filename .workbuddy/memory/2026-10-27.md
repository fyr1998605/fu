## fu41 vs fu 卡顿掉帧对比（只读分析，未改代码）

结论：fu 的卡顿是主线程被 GUI 阻塞，不是算力不足。串联链：
waitKey(1) 每轮都执行(Fu.cpp:562-566) → spinOnce 迟到 → 订阅 queue=1 覆盖丢帧
→ 图像超 50ms → BuffTimeSynchronizer::Expired → "Dropped frame"。

fu 侧具体浪费：
- Fu.cpp:536-540 每收到帧就 clone 整幅(3.75MiB)，120fps ≈ 450MiB/s
- buff_node_runtime.hpp:44-45 双份 clone；buff_recognizer.cpp:397 detector 再 clone
- getMultiBoxes 全量候选提关键点+O(n²) NMS；refineRCenter 对整帧 findContours(CHAIN_APPROX_NONE)
- Fu.cpp:529-530 控制期限复用 50ms IMU 等待，30fps 下必误触发 aiming disabled

fu41 对应处理（6 层）：独立 CallbackQueue+AsyncSpinner+std::thread+nice(10)
（Fu.cpp:649-657, buff_node_runtime.hpp:239-299）；BuffDisplayFrameQueue 8 帧有界丢最旧；
frame 与 frame_ 共享 buffer；top-64 候选截断 + R 中心 ROI 化 + SIMPLE 轮廓 + 256 轮廓截断；
相机 120→30fps/曝光 2300→1800/GPU+LATENCY+num_streams(1)；
控制超时独立 0.15；frame_processed 一图只处理一次；加 loop_gap/_BUFF_PROFILE/HK_CAMERA 诊断。

移植优先级：显示线程化 > 去三处 clone > top-K+ROI > frame_processed > 降帧率 > 超时解耦。

## 大符 RANSAC 拟合耗时与节奏（读码 + 基准 CSV）

单次 fit()：max_iterations=200，每次 3 点抽样 + 3×3 FullPivLU + 全滑窗(≤300 点)内点统计。
最坏 200×300=6 万次 sin() ≈1.5ms；实测 max 1.21ms / p99 0.70ms（干净输入）。
噪声大反而快：max 0.30ms，因为幅值/条件数门限提前 reject，不进内点循环。
数据源 docs/benchmarks/buff_prediction_comparison_2026-10-11.csv。

节奏：fit_every_n_samples=5，每 5 个被接受样本拟合一次 → 30fps≈167ms 一次，120fps≈42ms 一次；
摊到每帧约 0.15ms，尖峰集中在拟合帧。fit 在 Predict 阶段，看 [BUFF_TIMING] predict= 即可。

真正代价不是时间而是起手：min_inliers=100 且内点在整窗上数，窗口不足 100 点 ready() 恒 false
→ 30fps 连续有效观测约 3.3s 才出第一次有效预测；kMaxSamples=300 即 10s 滑窗，对变转速响应偏慢。
