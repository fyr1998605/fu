## 原问题与新的时间链路

原 Fu 在图像回调到达时读取 steady_clock，用这个时间进行识别关联、大小符
预测及世界观测更新；IMU 只取距离图像戳最近的样本，最大允许相差 50 ms。
正式角度输出又叠加最新串口 Pitch/Yaw。同一帧因此可能混合图像源时间、
回调时间和最新姿态，处理/传输抖动也会进入角速度估计。

现在的链路是：

1. HIK 在 SDK 返回完整帧后、格式转换和复制之前读取主机 ROS 时间。图像与
   时间戳在同一互斥锁内保存、取出；Image 和 CameraInfo 共用该戳。
2. 串口在 read_some 返回后打戳，记录每批字节的接收时间，完整包使用最后
   一个字节所在批次的戳。保留后续半包/包，不用旧解码结果刷新时间戳。
   `/RmSerialData` 与 `/imu/data_raw` 共用一次扣除延迟后的包时间。
3. Fu 缓存 0.5 秒姿态，最多 512 个样本。只接受精确同戳样本或图像时间两侧
   的合法括号，跨度默认不超过 30 ms。RPY 采用最短角距离插值，四元数独立
   SLERP 并归一化，保留原始四元数坐标约定及 RPY 安装偏移的关系。
4. ROS 图像订阅队列仍为 1，Fu 内部最多保留 8 张带源时间戳的图像。每次
   取最新可对齐帧并丢弃更早帧，较新的未匹配帧继续等待，避免连续输入把
   待匹配时间戳不断推向未来。每张图独立等待最多 50 ms，先检查超时再
   检查姿态，不降级为最近/最新姿态。超时使用 wall/steady 时间。
5. 识别关联、小符相位卡尔曼、大符 RANSAC 与可选世界 EKF 都使用同一个
   `image.header.stamp`。steady_clock 只负责性能统计和等待期限。
6. 图像派生的相对角叠加图像时刻 Pitch/Yaw，不再混入最新姿态。失效保持命令、
   机械保护反馈及弹速继续使用实时串口数据，原限幅、弹道和发送协议保持。
7. `/clock` 回拨清空姿态缓存、待处理图像、识别关联、大小符和世界模型状态、
   延迟估计及恢复计数。迟到的旧戳包被拒绝，不把普通乱序当成时间回拨。
   推理/求解结束后再次检查时钟，防止把旧时间域结果下发。
8. 可选 `/buff/reprojection_image` 保留源图像 stamp/frame_id；在同一张图上
   绘制该时刻观测/重投影和未来预测点。未来预测点是提前量预测，不能解释为
   与源图像同时刻的观测。ROS 发布器可自行更新 Header.seq，不用它配对时间。

原神经网络权重、预处理、输出解析、关键点映射、NMS、阈值和 R 点精化没有
修改，原兼容性 SHA256 检查仍通过。待处理图像上的 HUD 不会进入神经网络，
检测始终读取独立保留的原图。

## 配置和诊断

Fu 参数位于 `src/rm_tracker/config/rm_fu.yaml`：

```yaml
buff_imu_history_seconds: 0.5
buff_max_imu_bracket_gap_seconds: 0.03
buff_max_imu_wait_seconds: 0.05
buff_imu_stamp_offset_seconds: 0.0
buff_publish_debug_image: false
```

`buff_imu_stamp_offset_seconds` 的定义为“校正 IMU 戳 = 消息戳 + 偏移”，仅在
进入缓存时加一次。驱动已扣过对应延迟时不要重复补偿。时间参数必须有限，
历史/等待/括号跨度必须为正，括号跨度不得大于历史范围。

相机 `frame_receipt_delay_sec` 和串口 YAML `Time.receive_delay_sec` 定义为
“接收戳减去采样/曝光延迟估计”，本次均默认 0，尚未做实车标定。没有照搬
自瞄项目的 8.5 ms 初始估计，因为其文档也明确说明需要实测。可单独设置相机：

```bash
roslaunch rm_hikcamera rm_hikcamera.launch frame_receipt_delay_sec:=0.0085
```

上例只示意传参，不是推荐标定值。相机和串口是自瞄/能量机关共享的数据源，
共享启动中若配置驱动延迟，还需检查 Identify 原有 timeCompensation，避免
重复扣除。串口 36 字节包格式和消息字段未改变。

诊断话题：

| 话题 | 意义 |
| --- | --- |
| `/buff/image_pose_time_error_ms` | 插值姿态时间减图像源时间，单位 ms |
| `/buff/sync_bracket` | Header 是源图像；x/y 是前后样本相对图像的 ms，z 是跨度 |
| `/buff/reprojection_image` | 开启发布且有订阅时输出原分辨率的同戳调试图 |

窗口等待期间显示 `SYNC WAIT`。`[BUFF_SYNC]` 记录括号、残差和丢弃原因，
`[BUFF_TIMING]` 继续记录回调、推理、显示等耗时。没有合法姿态时不生成观测，
所以更新时间率可能降低；这是拒绝错时数据的结果，应核实输入戳和 IMU 频率。
固定视觉/电控提前量参数及自动延迟开关保持原配置，尚未重新标定其数值。
视觉处理延迟与电控指令延迟继续分别获取，再与弹丸飞行时间合成提前量；
视觉自动估计只更新视觉分量。图像/姿态时间戳校正用于观测对齐，不另外向
提前量叠加一份同步偏移。

## 学妹审核时重点核对

- 相机帧/戳原子配对、串口末字节打戳与半包保留是否符合微机版本。
- 图像时刻姿态用于相对角叠加，而实时反馈用于保持/机械保护的界限。
- 输入时间域、IMU 括号跨度与等待期限是否适合现场频率；校准参数是否重复。
- Gazebo/回放回拨后是否清空各模型状态；重投影图是否与源图像同戳。
