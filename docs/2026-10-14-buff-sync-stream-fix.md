# 连续时间同步、串口收发与缺数据控制修复

修复分支：`bugfix/buff-sync-stream-serial`，基于维护分支
`ros1-auto_aim-fu` 的 `1fa2bba`。提交 PR 后等待队友审核。

## 参考与修复

参考 ROS1 自瞄 `new_Rmidentify.hpp::serialAt` 的同戳/两侧括号与最短角
插值原则，参考 ROS2 自瞄 `RmTracker.hpp` 的有界时间戳缓存，以及
`rm_serial` 的命令邮箱、单线程 I/O、5 ms 接收轮询设计。两份自瞄参考
目录均只读，没有修改、同步或启动其现有仿真环境。

1. 原 Fu 只有一个待匹配图像时间戳，新图像不断覆盖它。实际节点在连续
   200 帧、姿态源时间滞后 20 ms 时对齐成功 0 次。现在缓存最多 8 帧，
   选最新可对齐的图像，丢弃更早图像，并保留较新的未匹配图像。
   容量覆盖当前相机发布上限 120 Hz 下的默认 50 ms 等待。
2. 每张图像单独记录 wall 到达时刻，先剔除过期帧，再查姿态括号。
   在等待 100 ms 后才补齐括号的帧，不再绕过默认 50 ms 期限。
3. 图像内容、Header 和内部序号一起缓存。回调借用不可变消息像素；
   匹配后才复制到算法自己的原图和绘图副本。预测与重投影使用被选中
   图像的时间戳，不能把较新图像内容配给较旧姿态。
4. 串口 ROS 回调只在互斥锁下保存最新命令，唯一 I/O 线程完成接收和发送。
   接收轮询最多等待 5 ms，静默时仍能发送待处理命令和响应退出。
   8 字节命令完整写入，断连或读写失败由 I/O 线程报告并退出供 launch 重启。
5. `.gitattributes` 指定 shell 脚本使用 LF，修复 Windows 拉取后在 WSL
   出现 `pipefail\r: invalid option name` 的问题。
6. 删除实车串口启动缺设备时自动仿真的分支，报错退出且不发布伪造姿态；
   未编译的 `serial copy.cpp` 也移除同一分支。所有 launch 的 `sim_mode`
   默认 false，只有用户显式设为 true 才启动测试数据源。
7. 按电控协议修正输出：0=无有效目标观测，1=观测到但尚不能自瞄，
   3=观测、预测和解算有效，进入自瞄。Fu 模型初始化/解算失败会明确发 1，
   识别失败、缺姿态与同步过期发 0；有效预测改为发 3。相机停止且缓存已
   清空时也检查最后一次输出的 wall 时间，超过现有等待期限（默认 50 ms）
   发 0。等待中的新回调不能刷新这个期限。退出 Fu 模式时只发一次 0，
   解除之前的自瞄状态后交还装甲板控制。期限检查由主循环执行，不能在
   同步推理阻塞期间保证精确 50 ms 停止，仍需实车验证电控的超时策略。
8. 检查统一启动中的装甲板链路，发现缺串口姿态时使用默认零姿态、停止
   收包后使用旧姿态，以及 TF 缺失后返回零位姿的路径。两个编译中的
   identify 入口都增加真实姿态/图像有效性与 200 ms 新鲜度检查；tracker
   也检查姿态及目标数据的 wall 到达时间，重复源戳不续期。200 ms 沿用
   原装甲板数据过期界限，暂停 /clock 时也能失效。
   装甲板消息使用源图像时间，转换失败不会给旧图装上新戳。
   TF 查询缺失直接返回失败，不再构造零位姿或阻塞等待 1 秒；异常退出
   本帧时停止控制。没有当前选中目标观测时不把纯预测结果当作自瞄状态；
   有观测但模型尚未准备好发 1，有效角度发 3，无观测发 0。

神经网络权重、预处理、输出解析、关键点映射、NMS、阈值和 R 点精化
没有修改。大小符预测模型、锁靶、弹道、延迟解耦与期望角话题保持。
36 字节输入和 8 字节输出的字段、角度缩放保持，控制码按用户确认的
协议使用。装甲板的这些保护不等同于移植其 ROS1/ROS2 完整同戳插值实现；
本次没有改变识别算法、标定、选靶或运动模型。

## 验证

- `bash scripts/test_buff.sh`：19 个 CTest 目标全部通过。包含 9 项串口 PTY
  检查；新增命令只由 I/O 所有者发送、最新命令合并、静默有界等待和断连
  报告检查。原时间戳、拆包和延迟只扣一次检查继续通过。
- 同步单元测试覆盖持续 100 Hz 输入、20/25 ms 姿态滞后、Unix 时间戳、
  过期后补齐括号、每帧独立期限、容量限制、递增源时间和源序号，以及
  原来的 SLERP、±π、乱序、重复、零戳与回拨检查。
- 实际 Fu 节点在默认 50 ms 等待、200 张连续图像与 20 ms 姿态滞后下，
  本机此次对齐成功 190 次；原版本同一场景为 0 次。数量受调度与最新帧
  丢弃策略影响，不保证每张输入都被处理，也不代表检测或击打帧率。
- 扩展后的实际节点 ROS 消息测试：small/big 各通过原单帧边界检查，并分别
  最后一次对齐 163/141 张连续流图像；源 stamp、frame_id、像素标记一致且时间递增。
  此脚本保留 150 ms 消息投递余量；默认 50 ms 另外由上面的节点复现和
  单元测试验证。软件姿态插值时间残差为 0 ms。
- Fu、实车串口节点、HIK 相机节点在 ROS Noetic 环境编译链接通过。
- 神经网络兼容性 SHA256 与现有大小符、选靶回归通过。
- 实际串口可执行文件缺设备返回 1，没有发布伪造 RmSerial/IMU；显式仿真
  入口单独验证。真实 PTY 证明 0、1、3 原样进入 8 字节输出。
- 实际 tracker 类验证缺姿态、非法姿态、停止更新、重复戳、暂停时钟、
  目标过期和未来戳会解除先前的自瞄状态，缺 TF 立即失败；Fu 空白图像及
  缺 IMU 括号输出 0，退出 Fu 模式发一次 0 后停止发布控制命令。
  两个 identify 入口的语法编译通过。

复现实际节点时间链路（独立 ROS master，不连接电控）：

```bash
source /opt/ros/noetic/setup.bash
source .cache/buff-ros-messages/devel/setup.bash
python3 scripts/run_ros_test.py python3 scripts/test_buff_time_sync_ros.py \
  --fu-binary /absolute/path/to/Fu \
  --model-path /absolute/path/to/buff_repvgg.xml
```

输入空白/像素标记图像仅验证时间链路和图像所有权；实车检测、闭环击打、
物理拔插恢复及相机/MCU 固定延迟标定尚未验证。

## 全链路排查与现场验证

| 链路 | 缺输入的处理 |
| --- | --- |
| HIK 相机 | 找不到设备退出；取帧失败不产生图像，连续失败退出；图像只取一次并保留原戳 |
| 串口 | 缺设备退出；静默不产生姿态；断连/读写错误退出；不会切换仿真 |
| Buff 图像与 IMU | 零戳、乱序、无合法括号拒绝；过期发 0，不用最近姿态/单位四元数替代 |
| 神经网络与关联 | 没有有效当前观测时不发自瞄角度；模型缺文件/初始化失败没有替代检测器 |
| 小符/大符预测 | 单一选定模型；未准备好/更新拒绝不切 FFT、变速或假定角速度路径 |
| PnP/世界 EKF | 缺当前帧姿态或解算无效不发 3；世界模型未就绪不转像素路径 |
| 装甲识别/跟踪/TF | 缺或过期输入拒绝，TF 缺失不构造零位姿，停止控制 |
| 控制输出 | 无观测 0、仅观测 1、有效自瞄 3；有限值检查；暂停时钟仍有 wall 超时 |

显式仿真入口、测试输入和调试弹道可视化保留；它们没有“实车缺数据自动
启用”的入口。历史未编译的识别/跟踪副本不作为当前运行链路，实际检查
以 CMake 可执行目标与 launch 入口为准。常量标定/配置默认值不作为
缺传感器数据的替代样本。

- 没有套用自瞄的 8.5 ms 相机延迟估计，也没有改已标定的安装偏移。
  硬件采样时间仍需要现场数据与电控协议支持。
