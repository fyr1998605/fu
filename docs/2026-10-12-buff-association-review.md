# 双亮扇叶关联、切靶滞后与模式显示

本次从维护分支 `ros1-auto_aim-fu` 的 `2f4c164` 建立
`bugfix/buff-target-association`，通过 PR 合并，不直接推送维护分支。

## 视频和现场信息能说明什么

提供的视频是手机拍摄识别窗口，约 36.28 秒、25 fps。约 10.34 秒处可以看到
两块同时亮起的扇叶和选择框。画面没有大小符标识；现场暂时拿不到启动日志和
运行提交号，所以无法确认视频使用的预测模式、是否已经包含上一轮修改。
手机录像也不能区分相机断流、推理阻塞、GUI 阻塞，窗口卡顿的根因仍需微机
`[BUFF_TIMING]` 日志核实。此次不把回归通过解释为实机卡顿已经解决。

## 已确认的代码问题与修复

1. 旧锁靶按屏幕像素直线速度外推，选取最近候选，没有旋转扇叶的稳定身份。
   后续跳变门限又使用未经补偿的位置，云台移动也可能被当成换靶。现在使用
   `atan2(Fan-R)`、上一帧运动模型的角速度和五个相隔 72° 的位置进行关联。
   每个 ID 只接收一个观测，所有关联成功的可见扇叶共同更新整轮相位。
2. 默认 `locked` 在大小符都生效。锁定 ID 仍可见时保持选择，不因置信度变化
   换靶。锁定 ID 消失后，新 ID 通常需要连续三帧确认；配置的失锁超时也能结束
   等待。确认中没有击打预测输出，保留已学习的运动模型，不返回旧坐标作为
   新一帧观测。约 25 fps 时连续三帧从第一帧到确认约 80 ms。
3. 旧跳变等待/几何拒绝有返回缓存坐标且报告成功的路径，导致预测器把旧角度
   和新时间配对。现在识别返回成功只代表本帧的新观测。
4. 切靶后旧框和角点继续 EMA，产生跨扇叶插值。现在确认 ID 改变时重置几何
   平滑，检测框直接显示当前框；角点形状在靶心局部坐标中平滑。小符预测使用
   当前相机空间的 R 与半径，并立即接受已由关联层确认的扇叶锚点。
5. 首帧初始化后同一图像再次识别，造成两次推理。现在复用首帧识别结果，且
   识别、关联和预测使用相同的图像到达单调时钟。
6. 画面底部显示 `BUFF: BIG / RANSAC` 或 `BUFF: SMALL / KALMAN`，同时显示
   当前 ID、激活状态、预测是否就绪和帧号。缺少新观测时不绘制旧框。串口
   `ShootFlag='f'` 日志改为“能量机关激活”；该字符不区分大小符。

这次没有改变大符正弦拟合算法。大符仍只有 RANSAC 正弦积分路径，小符仍只有
相位卡尔曼路径。关联层的角速度用于匹配身份，不产生额外的击打预测或兜底。
换靶确认等待时已有有效整轮关联，不再次清空大符输出就绪计数；真正失去关联
仍需要重新确认就绪。大符的初次拟合暖机仍受原来的最少内点数影响。

## 神经网络适配保护

沿用现有 `buff_repvgg.xml/.bin`，未修改权重、640×640 预处理、颜色类别、
输出解析、9→6 关键点映射、置信度阈值、NMS 或传统 R 点精化。识别阶段仍复制
一份图像给会画图的原检测器，防止标注污染后续图像处理。尝试过的候选去重及
R 点局部处理优化没有纳入最终修改。

兼容性回归固定检测器和 R 点精化的 SHA256，与维护分支 `2f4c164` 完全相同。
修改只作用于模型输出之后的关联、选择、几何平滑及显示。模型只有 red/blue
两类，接口没有显式“已命中”字段；切靶依赖原模型对可击打灯效的识别契约。
如果原模型还会输出已命中的扇叶，需要核实训练标注和灯效适配，不能凭本次
锁靶逻辑宣称已经判定命中。也没有把“亮两个”直接作为大小符自动判定条件。

## 借鉴的开源实现

算法思路参照本地收藏，按现有二维观测接口重新实现，未替换识别模型：

- 常州 `Climber_Vision_26-main/tasks/auto_buff/buff_big_group.cpp`：整轮运动
  模型与物理扇叶 ID 分离；`BigTargetSelector` 优先保持可见的锁定 ID。
- 吉林 `jlu_vision_26-master/src/auto_buff/buff_tracker/src/targets.cpp`：按
  预测的五扇叶位置和 roll 残差匹配，并限制同一帧每个 ID 最多匹配一次。
- 浙大 `HWauto_buff2026-main/src/tracker/buff_tracker.cpp`：RANSAC 的职责
  是估计大符角速度正弦曲线；它不能替代检测关联或可击打扇叶选择。

关联使用 0.30 rad 的相位残差门限，小于半个扇叶间隔，保留半径一致性约束。
这是图像平面的匹配，能消除共同像素平移的影响；严重透视变化、R 点错误和
长期遮挡仍可能失去身份，不等价于世界坐标系完整运动补偿。

已查询到的[官方 2026 V1.3 手册第 107 页](https://bbs-web-static.robomaster.com/c85923a9d793448288b5071f88a289721770635192667/RoboMaster%202026%20%E6%9C%BA%E7%94%B2%E5%A4%A7%E5%B8%88%E8%B6%85%E7%BA%A7%E5%AF%B9%E6%8A%97%E8%B5%9B%E6%AF%94%E8%B5%9B%E8%A7%84%E5%88%99%E6%89%8B%E5%86%8CV1.3.0%EF%BC%8820260209%EF%BC%89.pdf)
描述先点亮两块，第一块有 2.5 秒击打窗口，命中第一块后有 1 秒击打另一块。
这是已查到的版本说明，不代替训练台实际设置或更新版本规则。本次没有按固定
1 秒定时换靶，也没有仅凭开火推定已经命中。整轮模型跨灯效组保持，换靶只改变
击打扇叶锚点。当前接口缺少命中/灯效阶段时间，无法保证弹丸到达时目标仍有效。

## 验证和使用

`bash scripts/test_buff.sh` 运行 12 个 C++ 回归和 7 项 Python 契约检查。
覆盖正反转、双亮置信度翻转、大幅共同平移、短漏检、连续换靶、重复观测、
错误半径、长失联、切靶角点重置及现有神经网络接口兼容性。

新增流水线测试以 25 fps 模拟 40 秒，故意每 1 秒换一对，组内 0.4 秒先移除
一块，叠加角度噪声和相机平移。两个方向各确认 72 次切换、接受 778/1000
个选中观测，有效预测分别为 676 和 673 次；其余包括初次拟合暖机和选靶确认
等待，不能解释成命中率。换靶不清空正弦拟合历史。

Fu 在 ROS Noetic / OpenCV 4.2 / OpenVINO 2022.3 下完成编译和链接。该环境
不是微机，尚未通过真实相机、串口和弹丸实测；上一份诊断文档中列出的旧配置
检查失败仍没有通过改变控制协议来规避。

默认 YAML 仍为 `small`。启动时可以明确覆盖：

```bash
roslaunch rm_tracker rm_fu.launch buff_move_mode:=big
roslaunch rm_tracker rm_fu.launch buff_move_mode:=small
```

不传该参数时沿用 `fu_config` 中的模式。实际部署仍需提供原有模型路径和相机
标定。模式不会根据候选数量自动变化；现场以窗口底部标识和启动日志核对。
继续出现窗口停顿时保存 `[BUFF_TIMING]`，并做 `buff_show_image: false` 的同场景
对照，区分推理、消息到达及显示阶段。
