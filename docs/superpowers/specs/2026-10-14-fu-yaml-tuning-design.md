# Fu 统一 YAML 调参设计

## 目标

让 Fu 的现场调参集中在 `src/rm_tracker/config/rm_fu.yaml`。修改该 YAML 后，执行现有的 `roslaunch rm_tracker rm_fu.launch` 即可使用新参数，不需要修改 C++ 源码或在 launch 命令中重复传参。

## 范围

迁移 Fu 实际运行路径中会影响识别、跟踪、预测、时间补偿、弹道角度和输出保护的可调参数，包括：

- 模型路径、敌方颜色和运行模式；
- YOLO 置信度/NMS 阈值，以及 R 中心图像精化参数；
- 小符相位跟踪器和五扇叶关联的速度、残差、平滑、确认和半径门限；
- 大符 RANSAC 拟合与预测门控参数；
- PnP 尺寸、相机标定和坐标转换配置；
- 视觉/电控延迟、世界 EKF、IMU 时间同步和调试显示；
- pitch/yaw 固定补偿、云台角度限幅和卡死恢复参数。

固定模型维度、关键点布局、单位换算、数组长度和不可安全调节的算法结构常量继续保留在代码中。已有参数名称保持兼容；新增参数使用 `buff_` 前缀，避免与装甲板节点冲突。

## 配置结构

`rm_fu.yaml` 顶部增加“现场调参区”，按启动、识别、跟踪预测、时间同步、PnP/弹道、输出保护分组。每个参数保留当前运行默认值，并写明单位和作用。现有坐标转换块继续位于文件后部，因为 `CoordinateTransformer` 直接读取该文件的结构化节点。

启动文件保留 `fu_config` 参数并加载整份 YAML。模型路径和敌方颜色也从 YAML 读取；launch 中只保留 `fu_config` 作为文件入口，避免 launch 参数覆盖 YAML 中的调参值。为兼容已有调用，显式传入的 `fu_config` 仍可指向另一份同结构配置。

## 运行时读取

Fu 启动时通过私有 `NodeHandle` 读取 YAML 中的参数，并对有限性、正值、上下界和枚举值做校验。非法值回退到当前默认值并记录警告；无法继续运行的结构性错误（例如相机矩阵长度不正确或模式非法）仍直接退出。识别器、大小符预测器、世界跟踪器和输出保护分别接收已校验的配置对象，避免各模块重复读取 ROS 参数。

识别器构造函数新增配置参数，用于传递置信度、NMS 和 R 中心精化配置。小符跟踪器、五扇叶关联、变速预测器和输出保护增加显式配置入口；不改变现有默认算法流程。时间补偿仍由弹道飞行时间、视觉延迟和电控延迟合成，YAML 只控制各组成项及其校验范围。

## 数据流

```text
rm_fu.yaml
    ↓ rosparam load
Fu main: 读取、校验、构造配置
    ├─ BuffRecognizer
    ├─ SmallBuffPhaseTracker / BuffBladeAssociation
    ├─ BigBuffPredictor / RANSAC gate
    ├─ BuffWorldTracker / BuffTimeSynchronizer
    └─ PnP、弹道、角度输出保护
```

运行日志打印模式、模型、关键识别阈值、预测器参数、延迟和输出保护摘要，便于确认现场实际加载的是哪份 YAML。

## 兼容性和错误处理

- 不提供的新参数使用现有硬编码默认值，旧配置仍可启动。
- 参数为 NaN、无穷、负数或超出物理范围时，使用模块默认值并输出一次警告。
- `buff_move_mode` 只接受 `small` 或 `big`。
- 相机矩阵和畸变数组长度错误、坐标转换配置无效、时间同步结构参数无效时保持现有启动失败行为。
- `rm_fu.launch` 的默认配置路径保持 `$(find rm_tracker)/config/rm_fu.yaml`。

## 验证

增加/更新配置契约测试，检查：

1. launch 加载专用 Fu YAML，且不再通过 launch 参数覆盖调参字段；
2. 识别器和各预测器读取新增参数；
3. YAML 中的默认值与当前代码行为一致；
4. 配置文件可被 ROS/YAML 解析，现有 Fu 回归测试和预测器测试通过；
5. `git diff --check` 通过。

验证完成后，用文件链接交付 `rm_fu.yaml`、相关源文件和测试结果。
